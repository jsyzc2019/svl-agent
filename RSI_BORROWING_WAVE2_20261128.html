二、最值得先碰的三条 · 展开

B1摄食来源门控——双重证据，最硬

这不是"发现 bug"，而是论文提示的一道额外防线。本仓的 evidence_tier 本就是可信度标签（设计选择是"都进池，由 self_modify 的经验验证筛"），并非缺陷。但 Trusting Trust 的要求更严：投毒源会跨代遗传，且"用干净基准继续演化仍持续"。而我们手上恰好有活证据——三轮编号核实里，用户给的 5 条链接 5/5 错配、公众号清单 13 引用 错 10，错的全是二手转述（新闻站 / 营销页 / 公众号），一手 arXiv 源零错配。

证据：frontier_seeds.json 共 14 条，tier B=10 / C=4；runtime_policy.json 的 registered_frontier_seeds = 14 条，即 C 级（F02 CSDN、F06/F08 eigent.ai、F07 腾讯新闻）全部与 B 级同等注册。self_modify() 源码中无 tier 相关判断。

借鉴而非照搬：论文针对"自改进数据可被投毒"，本仓针对"摄食种子来源可信度"。同构在"质疑每个数据源"。最小动作是给 explore_pool 的候选标注 tier 并在议程 rationale 里显示（零风险），进阶门槛化才需授权。

B2别把轨迹压扁成标签——论文最强的一条

Meta-Harness 这篇的核心不是"改进循环"，而是喂给 proposer 的信息形态：它让 proposer 用文件系统选择性访问全部历史的代码、分数、执行轨迹来形成假设，而不是看压缩摘要，换来 +7.7 分、少 4× token、单次最多 1000 万 token 诊断信息（超此前反馈预算 3 个数量级）。原文的判词很锋利：

"分数只说明有东西失败了，轨迹才能说明为什么失败——把完整轨迹交给提出改动的 agent。"

本仓恰恰在这点上"压扁"了：propose() 和 root_cause_trace() 都把方向转成 _tags_of 的词集合做 jaccard 相似度——这是一种标签级信号。而完整的 heartbeat_log（31KB）、path_traces（4.8KB）、失败原因台账都已落盘，决策时却不读全文。

诚实边界：本仓的 propose 是 novelty search（求多样性），Meta-Harness 的 proposer 是生成新 harness 假设（求能力），两者目标不同。这是"信号形态"维度的同构借鉴，不是照搬。最小动作：加一个可选的诊断字段，让 REORIENT 分支读近期失败轨迹全文写进 rationale，先只记录、不改选向。

B3验证器也要被验证——P0 只补了一颗牙

Who Verifies 把演化对象从"被评分的 artifact"换成"评分函数本身"（由带类型的缺陷检测器组合），三条承诺：锚定不可伪造之物、保持验证器可读、审计审计者。最刺的一句：

"去掉锚点守卫，验证器塌成 always-pass grader，但塌掉的验证器训练技能效果一样好——下游任务分数无法认证一个自我进化的验证器。"

P0 修的 verify_external.py 严格 id 集合相等，是补了一个具体的洞；但"验证器会不会整体塌缩"这件事，本仓没有常态化探针——静态审计是一次性外部动作，跑了就完了。这正好是论文说的第三条承诺缺位。

最小动作：verify_verifier() 只读器官，喂一组已知正/负例给当前判据，看是否全放行（塌缩成 always-pass）；结论结构跟随证据、篡改探针即翻转。这是负向自咬在"验证器层"的延伸。

三、明确不借鉴（延续既有裁决，不重复讨论）

  • 不照搬 L5 元自修改：Hyperagents 唯一够 L5 的工作增益 p>0.05、跨运行累积不显著；本仓连 L3 都在证明路上。（§4S22 / P2b）
  • 不用 agent 下游分数验证验证器：Who Verifies 已证伪——塌成 always-pass 也看不出。（§4S20）
  • 不加常规测试 CI：与"只留 GHA 一条真通道"裁决冲突。（§4S15）
  • 不自发 Ambient 心跳 / 后台守护：违 L0，AAS 判据未达 autotelic，昼夜节律靠外部授时因子是刻意设计。（§4av / §4bg）

四、一句话总览

第一波补的是"改动可信度"的证据密度；第二波指向的是改动的输入与来源可信度——喂给改进者的是什么信号（B2）、允许什么数据源进来（B1）、谁来盯住守门人（B3）。三条其实还是论文里那堵墙的延伸：让改动可信，比让改动发生更难。以上都是参谋建议，零代码改动，权威态未触碰，判定权归用户。
