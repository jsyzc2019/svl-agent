REA 拆软件，rea-video 拆视频：爆款背后的做法，AI 逐镜拆给你看

November 21, 2026 by fendouai

看到一条好视频，最让人着急的，往往是那句：这到底怎么做的？

产品在镜头里旋转，字幕踩着节拍弹出来，人物又自然地接上下一段动作。你想做一条自己的版本，却连第一步该打开剪辑软件、视频模型，还是 Blender，都拿不准。

最近看到的开源项目 rea-video，就是围绕这个问题做的：把视频逐镜拆开，判断制作方式，整理画面、声音和时间信息，再给出复刻路径。

我觉得它值得关注的地方，是让那些只能凭感觉描述的效果，变成可以讨论、修改和执行的步骤。

图1｜项目公开的产品视频对照。相似的成片观感，背后可能对应完全不同的制作路径。来源：rea-video 官方案例，非本文实测。

先看结果：一条视频，能拆出多少东西？

先看官方给出的混合视频案例：19 秒、10 个镜头，里面同时包含 AI 人物对话、代码界面和真实录屏。

普通观众看到的是一条完整短片。做视频的人需要知道的，却是每一段要准备什么、交给哪种工具，以及哪些素材必须自己提供。

图2｜混合片案例。这里的画面来自项目公开报告素材，不是本次运行生成的结果。

这个案例里有个很有意思的规划：5 个对话镜头虽然被界面画面隔开，但属于同一场景，项目给出的方案是合并生成，再剪回原时间线。

镜头切了五次，不一定要调用五次生成模型。

这个区别看着小，真正制作时却会影响角色一致性、生成次数和后期修改量。当然，能否合并还取决于目标模型的时长、参考输入和多镜头能力。

图3｜官方分镜总览局部（裁切）。可以看到连续视频如何被组织成逐镜头的分析对象；数值和分类以对应报告版本为准。

我愿意把 rea-video 的产物理解成一份“施工图”：先弄清楚各部分怎么做，再进入生产。

最实用的判断：这一段，真的需要视频模型吗？

再看一个很容易让人选错工具的场景：产品宣传片。

界面飞入、文字缩放、数据滚动、窗口叠加，看起来非常“AI”，但其中很多效果适合用代码精确实现。

rea-video 的中文说明中展示了一条 70 秒、12 镜头的产品片。作者对其制作方式的分析是：约 83% 为代码动效、12% 为录屏，并建议用 Remotion 工程重建。

图4｜产品宣传片案例。比例属于作者对该样片的分析，不代表所有宣传片的构成。

这类镜头里，文字要正确，按钮位置要稳定，产品界面要能看清。用代码编排动画，可以围绕具体元素修改；用真实录屏，则能保留软件的实际行为。

如果直接要求生成模型重做整个画面，这些需要精确控制的元素就可能变成反复返工的地方。

图5｜同一产品片的分镜资料局部（裁切）。图中顺序用于理解画面组织，实际重建仍需逐镜核对时间与动效。

所以我最看重的用途，是在投入生成成本之前，先选对制作方法。

对于电商团队、软件产品运营和经常做演示视频的人，这比单纯多生成几段素材，更接近真实工作里的问题。

它怎么判断：工具测量，加上模型看图

单看一张截图，很难确定它来自相机、3D 渲染还是生成模型。

rea-video 会先做视频和音频分析，再将多种证据放到一起：帧率与重复帧规律、画面噪声、整图运动、文件中的 AIGC 标识，以及文字、手部和物理细节等。

其中，工具负责测量，多模态模型补充画面理解。发生冲突或证据不足时，可以让能看图的 Agent 复核。

图6｜官方案例中的元素拆解图。把画面内部对象拆开，有助于分别处理主体、界面和叠加元素。

这里最容易被忽略的是：转码会改变证据。

实拍视频经过平台压缩，噪声可能被抹掉；帧率转换会引入重复帧。倘若仍按原始文件的特征去判断，就可能把真实拍摄误认成生成画面。

项目的评测文档专门记录了这类问题，也说明了哪些规则是在看过样本后调整的。

图7｜同一镜头的时序联系图。判断动作和画面变化，需要连续信息，单张关键帧并不足够。

这也决定了它的使用方式：报告里的分类应该连同证据一起读。尤其是压缩严重、固定机位或拍摄真实手机屏幕的片段，值得人工再看一遍。

拆出来的知识，怎么交给下一位 AI？

如果分析结果只是一大段聊天文字，后续使用起来还是很累。

rea-video 会输出给人阅读的报告，以及给 Agent 读取的 VIDEO.md 拆解包。前者帮助理解，后者把概览、时间线和逐镜信息分层组织。

为什么这个设计有用？因为修改不同部分，需要的上下文不同。

改字幕，需要文字与起止时间；换产品，需要相关镜头、主体与参考图；重新安排生成任务，需要场景关系和目标模型的能力。无需每次把整条视频的全部分析重新读一遍。

这使得一次拆解有机会成为后续制作的共同依据。对长期维护内容的团队，我认为它还有沉淀参考片制作方法的潜力；但成熟的素材库管理能力，不能由这个设计直接推导出来。

真正复刻时，哪些能自动，哪些仍要自己做？

项目提供与 capsule-cinema 的衔接方式：把拆解结果转成生成任务，调用模型制作，再按时间线组装。

不同类型的镜头仍然走不同路径：AI 画面调用相应模型；静图推拉可以本地处理；代码动效由 Agent 编写工程；实拍和真实录屏则需要准备对应素材。

图8｜官方实拍开箱案例。分析可以帮助理解机位与拍法，真正重拍仍需要产品、场地和拍摄执行。

字幕和花字也有单独的处理思路：将它们与画面生成分开，生成后再叠回。这让精确文字的修改更容易控制。

需要特别说明：所谓反推提示词，是根据画面提出一种可行的实现描述，无法证明原作者使用的就是这段提示词。同样，报告建议的模型和生成次数，也需要在实际执行中验证。

图9｜实拍案例分镜总览局部（裁切）。图片用于展示报告的组织形式；此处仅截取局部，完整顺序请查阅项目报告。

项目还展示了 AI 音乐 MV 等更长案例，说明它希望覆盖的对象不只是一类带货短片。不过，不同内容类型的可靠性差异很大，不能从一个成功案例推到所有视频。

图10｜官方 AI 音乐 MV 案例素材。制作来源与拆解结论以作者的案例说明为准。

普通电脑能用，但准确率和费用要分开看

基础环境是 Python 3.10 以上和 FFmpeg。依赖包括 OpenCV、NumPy、ONNX Runtime 等，声音分离等步骤支持 CPU 运行；首次使用相关功能需要下载模型。

也就是说，基础拆解不以高端独立显卡为前提。后续如果调用多模态 API 或生成视频，则要看所选服务的费用与硬件要求。

项目开源，并不意味着整个生产过程都没有成本。本文是基于文档、案例和评测记录的项目介绍，没有运行本机测速，也不将作者的示例耗时当成你的电脑速度。

准确率同样需要看具体配置。作者早期记录中，两条首次遇到的带货视频，仅工具判断为 46.4%，加入看图模型后为 63.9%，再经过 Agent 看图复核为 97.5%。后续从头解码重测，带货组的工具结果提高到 63.2%，但影视混剪仍只有 15.8%。

这些数字来自不同阶段的小样本实验，部分规则经过样本调优，部分集合还有缺失素材。它们说明看图复核的重要性，也提醒我们：不能把最高的一个数字，当成对所有视频的承诺。

我建议第一次使用时，选一条自己拍过、制作过程清楚的短片。对照真实情况检查镜头、声音和来源判断，比直接扔一条陌生长片更容易判断工具是否适合自己。

已经使用 Codex 或 Claude Code，可以按项目提供的方式开始：

安装 https://github.com/JuneYaooo/rea-video，
然后拆解这条视频：/path/to/video.mp4

安装好 CLI 后，基础命令是：

rea-video decompose ref.mp4 -o out/ref

截至本次取材，GitHub API 返回约 1.16 万 Star，仓库采用 Apache-2.0 许可证。热度值得关注，但我更愿意继续看它怎样处理误判、怎样让拆解结果真正进入制作。

对于我们这些经常收藏参考片的人，rea-video 提供了一个很具体的起点：下一次遇到喜欢的视频，可以先问清楚它由哪些部分构成，再决定自己要怎么做。

参考片中的画面、音乐和肖像，仍需分别确认使用权。学习结构与节奏后，用自己有权使用的素材重新制作，才是能持续使用的办法。

好的参考片不该只躺在收藏夹里。把做法看明白，才有机会拍出自己的下一条。
