本仓 vs Exo / Hyperagents · 三栏架构差距清单

2026-11-28 · 工作计划 P2b：整理"本仓已具备 / 可选借鉴 / 明确不采纳"三栏，每栏给理由 · 一页表格，零代码改动，判定权归用户

先定调：这份清单不是"本仓落后多少"的差距表，而是"哪些是本仓刻意选择"的说明表。三篇读下来最一致的结论是——大家都在想办法让改动可信，而不是只让改动发生。本仓从第一天起的纪律（预注册 SHA、逐字锚点、判定权归用户、不伪造日志）已经站在这堵墙上。

三栏对照

维度本仓已具备 ✓可选借鉴 ~明确不采纳 ✗
改动的可信闸门 判定权归用户 + constitution 锁 + 权威态哈希 + 预注册 SHA 先于取证。比 Exo/Hyperagents 都严。 Exo 的独立 guardian 外部检查、append-only 执行历史——本仓的负向自咬已部分覆盖。 把判定权交给 agent 自己或固定的 build-success 检查：那正是本仓宪法禁止的。
验证器本身 验证闸门 G1–G10、负向自咬、三方一致性校验。 Who Verifies 的"锚定不可伪造之物 + 审计审计者"——本轮留出集已落地第一版。 用 agent 下游分数验证验证器（已证伪：塌成 always-pass 也看不出）。
原始诊断经验 心跳账本、takeover_exec_log、错题本、root_cause_trace 全量落盘。 Meta-Harness 的文件系统全量轨迹喂 proposer——本仓已有数据，差的是"改前改后对打"。 把诊断经验压扁成分数摘要（Meta-Harness 证明信息不能压扁）。
增益归因 本轮已建 gain_attribution 样例（3 条）+ 留出集对打（+57.15pp±14.54pp）。 HDA 三类归因（过拟合/算力/残留）、Harness Ceiling 失败成分分类。 裸报分数不给标准误/归因（Winner's Curse：16 样本高估 13–20 分）。
节律与自主性 KERNEL 7.5.0 真实心跳 + GHA 自动 cron，NIGHT/slept=true；本仓独有。 — Exo 的运行时自编辑自由：论文自承有 intelligence floor，智能不够给自由也没用。
外层协议 判定权归用户是设计公理，写进宪法，不可由内核改。 Hyperagents 外层父代选择/评估协议固定——但那是实验安全约束，非公理。 照搬 Hyperagents 的元认知自修改：它连 L3 都还在证明路上，增益 p>0.05。
负面结果 §4S 全程留档 + 本轮 negative_results.jsonl（11 条）结构化。 No Second Run "账本是贡献" ——本仓已在收敛，可继续制度化。 只记成功不记失败（Winner's Curse：幸存者偏差让自报进度系统性乐观）。
CI 通道 只留 GHA 一条真通道，用户裁决。 — 加常规测试 CI——与"只留 GHA"裁决冲突，本清单不推翻。
一句话结论：本仓的"判定权归用户"比 Exo 的 build-success guardian、Hyperagents 的固定外层协议都更严——这是刻意选择，不是落后。差距不在"要不要把人留在环里"，而在"改动是否真的更好"的证据密度：这正是本周 P0/P1 在补的东西。
诚实边界：Exo/Hyperagents 的形态看似 L4/L5，但 Hyperagents 唯一够 L5 的工作增益 p>0.05、跨运行累积不显著；本仓 L2 扎实、L3 的 independent_tests 仍 partial、L5 未到。功能形态相近 ≠ 证据等级相近。本清单对照的是机制，不是宣布等级。

依据：Exo 深度报告（arXiv:2611.00463 + exoharness/exo 实查）、Hyperagents 深度报告（arXiv:2603.19461 + facebookresearch/HyperAgents 实查）、RSI 论文全文研读（9 篇）+ 本仓现状现场实读。零代码改动，权威态未触碰，判定权归用户。
