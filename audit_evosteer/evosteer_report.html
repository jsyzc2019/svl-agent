一、论文三大挑战与 EvoSteer 的应答

(i) Post-hoc evolution（事后演化）：现有编排只在轨迹之间修订技能/提示/拓扑——"orchestration still evolves only between trajectories, by revising skills, prompts, or topology after a batch of runs has ended"；配置错误的团队输出看似合理而难发现，"impossible to repair while the workflow is still being executed"。

(ii) Credit diffusion（信用扩散）：共享终端奖励下 "give every action the same coefficient of a single terminal advantage"，且 "learned state values confound how often a task is solved, execution noise, and structural choice"——低分是任务太难还是团队组织糟糕，无法分辨。

(iii) Uncalibrated skill admission（未校准准入）：技能由 judge 或成功计数准入，"such point estimates cannot separate insufficient evidence from a confirmed effect"；"no test tracks whether an admitted skill still helps on later tasks, it stays in the library and is never retired"。

EvoSteer 应答：在线自演化图编排——编排器从执行特征与价值估计动态构建并修复运行中团队，每轮一次原子编辑（含 rerun/drop），"a plausible but failing result can be redone mid-run"；AnchorTB 把子轨迹对冻结参考做平衡为每个动作分配系数；Validated Skill Admission 让候选先试用、配对反事实 + 共享 alpha-spending 预算序贯检验后才晋升/退役。

二、认知增量：从"事后修订"里切出两个独立可证伪拦截面

这篇论文最锋利的不是刷榜，而是把"自演化"拆成可审计的机制承诺。精研定位出两条现有门禁完全空白、可迁移、会拦的拦截面：

① 在线可修复性：声称"在线自演化"的系统，究竟能不能在同一运行执行中途做原子修复（rerun/drop），由执行特征与参考锚定价值驱动，而非批次后修订、只能追加节点、凭输出表面合理性。事后正确 ≠ 运行中途可修复。

② 技能准入校准：声称"技能库自演化"的系统，是否先试用后晋升、用配对反事实分离证据不足与确认效果、以共享预算序贯检验代替点估计、并具备退役/延迟机制。准入 ≠ 校准 ≠ 退役。

一句话收束：这篇论文最该带走的不是十二数据集的刷榜数字，而是对"自演化"三个字的拆解锋利度——事后改团队不叫在线修复，执行中途由执行特征驱动的 rerun/drop 才叫；共享终端奖励给每个动作同一系数不叫信用分配，对冻结参考做子轨迹平衡才叫；LLM judge 或成功计数准入不叫校准，配对反事实 + 共享预算序贯检验 + 退役才叫。本仓 28 道门禁量过判据来源、证明边界、记忆溯源，却没一道判过"编辑是否在同一次运行的中途发生"或"技能准入是否校准并可退役"。两把新尺子落地：online_repair_honesty（仅事后/无 rerun-drop/非执行驱动/价值无锚定→downgrade）与 skill_admission_calibration（未试用/无配对/无预算/无退役→downgrade）。信规则、不承诺有效、只认会拦的独立拦截面。
