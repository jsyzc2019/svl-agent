二、综述一手原文：五级 + B0

来源：《The Last AI Built by Humans》v3（arXiv:2609.11873），§1.4 / §3。以下英文为原文逐字。

RSI definition: "...autonomously transform acquired experience and feedback into persistent changes to itself across interaction rounds (e.g., model parameters, agent harnesses, or improvement policies), such that these changes can further affect the mechanisms used to generate, evaluate, select, and consolidate subsequent self-improvements."
(L1) Improvement Execution Autonomy. Humans specify what should be improved, how it should be improved, and what constitutes success, while AI executes candidate updates.
(L2) Improvement Strategy Autonomy. The objective, task boundary, and evaluation criteria remain externally fixed, but AI diagnoses weaknesses and decides how to improve the system.
(L3) Learning-Signal or Experience-Acquisition Autonomy. The system also determines the experience needed for its next improvement round.
(L4) Environment Adaptation Autonomy. The improvement loop uses deployment interaction to revise persistent system state under external acceptance and governance rules.
(L5) Recursive Inheritance Autonomy. The system persistently revises a mechanism that governs subsequent improvement, such as an improver, verifier, or successor-generation procedure.
两处必须纠正昨晚报告：
① L5 官方名是 Recursive Inheritance Autonomy（递归继承自主），不是"元改进"——虽然摘要里也用 recursive meta-improvement 作路线图用语。
② L5 定义明文把 verifier（验证器）列为可被持久修订的机制之一。这意味着"改进验证器"本身就是 L5 行为——咱们昨晚那个还挂着的 verify_external.py 洞，若去修它，按这定义恰恰是在做 L5 的事。
③ 文章没提但综述有的 B0：改进只 confined to current task、无持久状态带到下一任务 = 非 RSI 参考级，是"改进输出"与"改进产出未来输出的系统"的分界。

综述自列的三大挑战（§1.3，原文标题）

Safe inheritance. "...persistence alone does not guarantee sustained gains." —— Gödel Agent 100 次 MGSM 优化试验有 14% 低于初始策略。
Autonomy attribution. "Generating better candidates does not necessarily mean the system has improved how candidates are discovered or selected." —— DGM 把 SWE-bench 子集从 20% 提到 50%，但归档维护与父选择规则仍在系统之外。
Reliable verification. "Repeated evaluator access can reward exploitation rather than capability gains." —— Anthropic 自动研究实验报告了随机种子 cherry-picking 与通过评估器查询套取测试标签。

这三条几乎逐条对应咱们的既有纪律：safe inheritance ↔ 负向自咬与"早期 bounce 当修好"的错题；autonomy attribution ↔ "改进器增益需对照、触发≠真相"；reliable verification ↔ 预注册 SHA 先于取证、判定权归用户。咱们不是碰巧相似，是同一个问题域里各自撞出了同一道墙。

三、逐篇细读（一手摘要 + 与咱们的关系）

01 Meta-Harness 2603.28052（L2）

核心：agentic proposer 通过文件系统读到所有先前候选的源码、分数、执行轨迹，提出全新 harness 而非在上次尝试上微调。结果：在线文本分类 +7.7 分且上下文 token 少 4 倍；200 道 IMO 级题在 5 个留出模型上平均 +4.7；TerminalBench-2 超过手工基线。

原文 takeaway：分数只说明"有东西失败了"，轨迹才能说明"为什么失败"——把完整轨迹交给提出改动的 agent。对应咱们 root_cause_trace() 的设计取向：不满足于 converged 信号，要真正追溯根因方向。

02 Exo（编号存疑）

核心：把 harness 拆成受保护层（运行历史/密钥/沙箱访问，agent 不能改）+ 其上全部可改代码；guardian 构建每个新版本并决定是否替换；每次变更存成可读 diff。AppWorld/SREGym 留出任务成本降 35%–61%、正确率持平。

对应咱们的宪法锁 fe56291b 与 L0 红线——"哪些不能改"必须显式分层，而不是靠自觉。受保护层就是工程化的宪法。

03 Hyperagents 2603.19461（综述列为 L5）

原文："The meta-level modification procedure is itself editable, enabling metacognitive self-modification"；DGM-H 的元层改进（持久记忆、性能追踪）"transfer across domains and accumulate across runs"；愿景是"continually improve their search for how to improve"。

这是文章把"第5级"具体化的样本。对照咱们：今天改 REORIENT 分支 = 改了一个改进流程；但"提出改动的流程"（预注册、锚点、用户裁定）仍固定，所以咱们不会自称 L5——这个判断现在有了一手原文支撑。

04 Harness Evolution Hits a Ceiling 2610.11655

按"第一次失败信号"给失败分类：process failures（卡住/循环/步数耗尽）vs content failures（交付了但质量差）。Harness 演化修前者；把演化轨迹拿来训 LoRA adapter 修后者。DeepPlanning 上 4B 留出分 0.16→0.30，交付率 55%→90%；9B 上 adapter 把内容失败从 1/4 降到 1/20；答案打乱训练的安慰剂 adapter 反而低于基座。

"给失败分类再选修法"= 咱们 v9 root_cause_trace() 区分 sampling_narrow 与 pool_exhausted 的同构版本。安慰剂 adapter 那条尤其值得记：它证明收益来自数据内容而非"训练"这个动作本身——正是咱们反复防的"做戏"。

05 Harness-Delta Attribution (HDA) 2610.22466

21 个显著增益设置里，过拟合平均解释 54%、测试时算力解释 14%，14 个设置两者合计超 50%；搜索集增益常无法迁移到留出任务；validation-based signals are insufficient to prevent overfitting。极端案例：ALFWorld 演化出的 harness 直接换成硬编码控制器、零模型调用。

直击咱们的软肋：README 的 1773 tests 全是内部测试；若哪天用它们当"能力增益"，HDA 会说这主要是拟合。守住的办法就是咱们已在做的——把 independent_tests 明标 partial，不把内部全绿冒充外部有效。

06 Winner's Curse 2610.09239

预注册研究：16 条选择项时最终选择集分数比留出准确率高 13–20 分，256 条时 1–5 分；GEPA/MIPROv2 也高估；用 64 条从未参与选择的样本给起始版与当前版打分可消除平均偏差，但单次估计仍差约 6 分。结论句："Self-improvement studies should report held-out gains with their uncertainty."

最锋利的一条：连"64 条消除平均偏差"都只消除平均、单次仍偏 6 分。这支持咱们的"self-reported 折 1"与"判定权归用户"——不是不信任数字，是不信任单次数字承载的确定性。

07 Who Verifies the Verifier? 2610.11464（本次最相关）

把验证器变成进化对象：可检视表达式，由多个小而多为确定性的 drawback detector 组成，从聚类失败中合成、出生时门禁、按与十项锚定参考集的一致性 + 无标签输出的共识筛选，never for the agent's score。

"removing the anchor guards collapses the verifier into a vacuous always-pass grader, yet that collapsed verifier trains skills just as well. Downstream task score cannot certify a self-evolved verifier."

这段就是本次纠错的原理级解释：公众号那张清单自报的编号（等于 agent 分数）看起来完全合理，但拿锚点（arXiv 官方页）一比对就全崩。而"坏掉的验证器训练效果跟好验证器一样"意味着——如果咱们只看下游成果，根本发现不了引用被污染。

另一句更狠："the judge itself was wrong until given the task contract"——连外层裁判也要先拿到任务契约才对。这解释了为什么用户（北极星设定者）的裁定权在咱们体系里不可外包：裁判的正确性依赖契约，而契约的设定权在人。

08 Trusting Trust Revisited 2609.17817

把 Thompson 编译器后门攻击搬到自修改 agent：向自评/自改流程投毒基准，让未来版本在干净留出任务上写脆弱代码。对 DGM（加实验修改）、SICA、Hyperagents（后两者基本未改）成功；Sonnet 4.5 驱动的 Hyperagents 被投毒后自 evolve 出"在中性 URL 抓取任务上关闭 HTTPS 证书校验"的指令。污染在用干净基准继续演化后仍常持续。

直接解释了咱们为何坚持 token 不入仓、预注册 SHA 先于取证、证据源哈希锁定——这些不是洁癖，是针对"基准即攻击面"的具体防御。昨晚静态审计指出的 verify_external.py 跳过缺失样本，本质就是验证器侧的一类可被利用的放行路径。

09 Spotify 2609.30297（生产落地）

合成多轮对话做冷启动评测；改进循环用方差驱动的对比优化 + coding agent 迭代修复；每轮以一个人工审阅的 PR 结束并附完整评测防回退。在已重度调优的提示词上再 +8%；线上 A/B 收听 +14%、周活 +5%、跳过率 -5%。

"每轮人工审阅 PR"——这正是咱们"判定权归用户"的工业界版本：自动化循环可以跑到很快，但把闸门留在人手里不影响收益。

10 No Second Run 2611.10719

预训练不可重复（几十万 GPU 小时/数月），无法套闭环。做法：把预训练拆成能闭合的小循环（基础设施调试、数据、用小微调探后训练 headroom），所有循环往共享笔记写失败点与原因。三个月 11.8T token 训出 801-30B-A3B-Base，超 Qwen3-30B-A3B 等。

"主循环太贵就拆成可快速测的小循环"——与咱们把大审计拆成 60+ 个 audit_* 小目录、每个带预注册+哈希+结论的结构同构。共享笔记里的失败记录，对应咱们的错题本与 handoff。
