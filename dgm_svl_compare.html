A自改进的「改动对象」
DGM 侧
改 agent 自身的**可执行代码库**（prompt / tool / workflow，FM 权重冻结）。benchmark 分数作唯一适应度。
DGM_outer.py self_improve；coding_agent_polyglot.py:116 `code_model = CLAUDE_MODEL if not self_improve else OPENAI_MODEL`
SVL 本仓侧
改**判据语义 / 知识条目**（KnowledgeItem：trigger→action→support→evidence），不直接写产品代码；判据可证伪、可回滚、三层诚实结论。
knowledge_base.py KnowledgeItem + ingest()；README §设计原则 4「判据会被博弈，判据本身也要版本化」
扬长判定：缺点互补：DGM 直接动代码、见效快但攻击面大（附录 H 即删检测日志）；SVL 动判据语义、慢但稳，天然带版本/回滚。
→ 借给本仓（扬长避短）借 DGM 的「改动被编译后必须重新过完整 eval」纪律——SVL install 判据后可加一次 exact-commit 全量回归，不只是冻结子集。
→ 借给 DGM（相互借鉴）借 SVL 的「改动对象与判据分离」——若 DGM 把 self-modify 限定在判据/提示层而非检测逻辑，附录 H 那类删日志攻击面会收窄。

收敛：同构之下，究竟剩什么

共同底座：两者共享同一考古层：『保留失败踏脚石 + 用经验证判据 + 防评价函数被博弈 + 主体分层 + 诚实边界』——这是 RSI 共同体的共同底座，不是一方证明另一方。
真差异（根）：真差异只有一条根：DGM 优化的是『代码空间里的标量适应度』，探索规则冻结；SVL 优化的是『判据语义空间里的可证伪结构』，元规则入闭环。前者强在真实基准与可测量，后者强在防作弊与可自审。
借鉴方向：借鉴是双向的：SVL 最该补的是『真实 held-out 迁移检验 + 活体作弊回归样例 + 显式主体标注』；DGM 最该补的是『计分器不可篡改 + 元规则自审 + 形式化停止条件』。
入库决策：本次不新增 KB 条目——逐维对照后发现每条『差异』要么已被现有条目覆盖（KB-AUDIT07 / KB-SIM05 / KB-STRUCT02 / KB-R-MS01），要么是本仓当前未落地的功能差距（如真实沙箱），属观察而非可编译的新攻击面。
