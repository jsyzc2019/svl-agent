编译成的门禁：check_review_evaluation

文章 line 123："Any evaluation that treats all these as one end-to-end score won't capture this nuance." 本仓从未判过评估方案本身的分阶段/对照/分离口径，编译成会拦会判的代码：

  1. R0 NON_SEMANTIC_INPUT: 非 bool 字段 或 recall 非 None 且不在[0,1] → flag（拒绝对字面串/越界值判定，避开 §56 brittle 根因 KB-AUDIT01）
  2. R1 SINGLE_END_TO_END_SCORE: not staged_recall → block（把三阶段压成一个端到端分数=看不出系统丢了已找到的 bug，文章 line 123 明确该 nuance 会丢；KB-AUDIT04 口径对等）
  3. R2 NO_STABLE_CONTROL: not stable_control_used → downgrade（无稳定集对照=无法区分真发现与 over-flagging，line 122）
  4. R3 TUNING_TEST_LEAK: not tuning_test_separated → downgrade（tuning 与 fixed test 不分=过拟合 eval，line 122）
  5. R4 NO_ANSWER_KEY: not answer_key_scored → downgrade（不按『是否正确描述 bug』计分=分数口径失真，line 122）
  6. R5 FUNNEL_INVERTED: staged_recall 且 final_recall/raw_recall 均给出且 final_recall > raw_recall → flag（漏斗倒挂：验证过滤不该让召回凭空变高，口径可疑待核）
  7. R6 STAGED_CREDIBLE: 分阶段 + 稳定集对照 + tuning/test分离 + answer key + 漏斗不倒挂 → ok
