四、确定性 bug 修复：失败厂商 ≠ 判错厂商

初版 engine 的 present 只按 manifest 文件是否存在判定（git show d6a6aa4:engine.py 第 44 行，spawn 前已锁），把 429 失败的 ling 也算"已判"，2 家 4/4 就误落 CROSS_PARTIAL（语义="1 家判错"）。但 ling 是 API 失败没判，不是"判了判错"——算作分歧是伪造语义。prereg 原文已写明"任一厂商 API 失败 → INTERPRETER_CROSS_INCONCLUSIVE"。修法：present 只计 status==ok 且产出 tiers 者，失败厂商 tiers=None 如实记录，走 INCONCLUSIVE 分支。修工具不放宽、不重跑 ling（§113 明禁调到跑通）、不改 prereg（KB-META23）。

五、裁决：INTERPRETER_CROSS_INCONCLUSIVE（诚实的不完整结果）
