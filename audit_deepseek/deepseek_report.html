二、核心判断

不是"全家桶功能很全"，而是一个可迁移的独立拦截面。 官方文档反复提醒的事实：你传进去的 temperature/seed，在开了搜索后被服务端悄悄忽略；旧模型名还能调但后端已换；开了 safety_check 只是"基础风控"，内容安全/大模型登记/AI 标识义务仍在开发者；搜索工具本身免费了但结果 token 仍在计费。 这四层是"客户端声称的控制 vs 服务端实际裁决"的错位。本仓 20 道门禁判了调用接线、训练口径、检索污染、证明范围、介入授权、记忆作用域……却无一判这个维度。

六、三层诚实结论

一手可核：官方契约文本与源码事实：S03 明列被忽略参数清单（temperature/top_p/seed 等由服务端决定）、客户端只展示内容块并原样回传、safety_check=high 仅基础风控且合规义务在开发者；S05 明列服务端搜索工具本身不计费但结果 token 计费、deepseek-v4-flash 别名可调用但后端已下线；仓库 types.ts 明注 encrypted_content 客户端无法解密、signature 由服务端解密恢复上下文、parseEvent.ts 未识别事件静默丢弃。

scoped 与折扣：五来源同属 DeepSeek 一个主体（KB-STRUCT02 折 1），非独立验证；『1:1 复刻 App/轻松实现复杂对话/基础风控』为官方 self-reported（KB-RSI07），不采信为效果证据；价格是契约声明非实测；提出全家桶能力（capability）≠ 客户端真能控制（control）。

不可判定边界：客户端是否真的只依赖服务端裁决、加密内容是否真不可解密、安全风控是否真的有效、计费是否真按声明执行——本门只判『契约声明是否诚实披露控制边界』，不承诺系统行为有效（KB-R07/KB-AUDIT03 存在≠执行）；本门审读外部 API 契约与客户端，不判本仓。
