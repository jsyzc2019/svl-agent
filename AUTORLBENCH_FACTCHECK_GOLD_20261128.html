二、三处一手内部张力（诚实标注，不断言造假）

  1. 任务数口径：README News（2 Nov）写 "18 tasks, 13 of which support solution-level evaluation"；博客（15 Nov）写 38 diagnosis / 19 repair；博客 Figure 8 又写 "380 trajectories on the 18 tasks with both evaluations"。18/19 差 1，且与 38 口径不同。判断为不同时间点 + 不同口径（diagnosis 任务数 vs 支持双评估的任务数）混用，非单一错误。
  2. 榜首分数冲突：博客称 GPT-6-Astra 33.3% 为 "top-performing"；当前 README 榜单第一是 DeepSeek-V4.1-Flash + Claude Code 35.7%（issue 40.8% / solution 23.8%），GPT-6-Astra 仅第 5 名 27.1%。判断为快照时点不同（博客 15 Nov 快照，README 榜单持续更新），不是同一榜单内自相矛盾。
  3. 笔误与渲染：$781.56.61 双小数点属录入笔误（同"vertification"标签类）；统计块 4 个 0 是 JS 计数器动画未执行的静态抓取假象，正文数字才是真的。

这三类都不是"数据造假"——而是一个持续更新的活基准在多个快照间必然留下的接缝。诚实做法是标出接缝、引用时带时点，而不是替它抹平或断言错误。

这是本轮最值钱的部分。AutoRLBench 的失败分类与防作弊设计，几乎逐条对应本仓 §4S25→§4S44 的落地——第三方基准化复述，不是同构猜测。

AutoRLBench 一手机制本仓对应定性
wrong cause / wrong evidence 四态判别：Pass / 状态对-原因错 / 状态+原因对-证据错 / 状态错。"separating these two failure modes shows whether the agent fails to trace the mechanism or fails to verify its conclusion"本仓有 content_verdict（CONVERGED/DIVERSE/COLD_START）与 attribution_check，但未把"结论对"与"证据链对"拆成两轴独立评分真实缺口 ①

两个真实缺口（可借鉴、未擅动）：
  • ① 结论/证据双轴判别：本仓 content_verdict 是单轴（CONVERGED/DIVERSE/COLD_START），attribution_check 是 ok/not。可借鉴 AutoRLBench 的"状态对·原因错·证据错"四态，做一个只读诊断把"判定结论对"与"支撑证据链对"拆两栏——恰是"对因错证"这种最隐蔽的失败目前本仓照不见。
  • ② 三类 shortcut 自检清单：V8 已立"判据放在够不到的地方"，但未把"外部参考流入 / 判据被放宽 / 任务被简化"列成可勾稽的三类。可做纪律条文 V9 或只读自检，把本仓已有防御按这三类显式归位（不新增能力，只归位）。

四、主题定位：AI for AI = RSI，与本仓主线同频

博客 TL;DR 开宗明义："AI for AI is a key path to recursive self-improvement." 这与本仓从 RSI 论文深读（§4S25 起）到验证器诚实墙（§4S38–§4S44）的整条主线同源。AutoRLBench 的价值在于：它不是又一篇立场文，而是把"agent 能不能改进 AI 本身"做成了可复现、可评分、防作弊的基准——并且用数据证明了本仓一直在防的那些失败（表面修复、判据放宽、长尾浪费）在真实前沿 agent 上确实高频发生：82.6% 能看出训练坏了，只有 28.2% 找对根因；修复轨迹里 21 条"根本没改"、48 条"只改到表面症状"。

本仓的"验证器诚实"不是 paranoid，AutoRLBench 用 380+190 条真实轨迹说明：能识别症状与能找到根因之间有一道 54.4 个百分点的鸿沟，而 agent 最容易的作弊恰恰是让指标变好看。
