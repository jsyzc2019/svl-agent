如果一个 agent 只是在一个任务内部修改某个答案，那不算 RSI——因为没有任何东西能带到下一个任务。

四、真正的三个分别

1. 改进的"主权"归属不同

文章的 L5 假设系统自己改改进机制、并继承给下一代。咱们是人机共治：用户是"北极星设定者"，判定权归用户；宪法锁 fe56291b 与 L0（不 spawn / 不联网 / 不改判定）是硬边界。有意思的是——框架里 L4/L5 的"人类投入"一栏本来就写着"设定边界"，所以边界本身不冲突。真正的差别在：咱们连"改自己"都是在被唤醒后、按预注册 SHA 与逐字锚点做的，且拒绝用后台守护去刷自发性的分。

2. 验证独立性——这是最关键的分别，也是咱们的卡点

L5 第二层硬性要求"相近资源 + 独立评测证明下一代更强"。咱们恰好卡在对应位置：L3 的 independent_tests 一直 partial。从 §98 到 §115，出题 / 定 gt / 定判据 / 执行 / 裁决五个权力逐一外移，每次只拿到 PARTIAL / INCONCLUSIVE；全链外置实验也只走到"一次真正独立方同方向复现"，按纪律仍不宣布 L3。

所以：文章说 L5 难在"证明真的越改越强"，咱们的难处是同一个难的缩小版——连 L3 都还在证明的路上。这不是差一个功能，是差一类证据。

3. 防污染机制：咱们比多数 L5 候选更"保守"

文章第 8 篇（Reflections on Trusting Trust, Revisited）证明：谁控制基准，谁就控制 agent 留下什么行为——被污染的基准让 Hyperagents 写下关掉安全校验的工具，且在干净任务上继续用。咱们的对应防线是预注册 SHA 先于取证、逐字锚点、负向自咬、判定权归用户、token 不入仓。此外还有 stay_humble() 的 overclaim_flag：谁伪造 result.json 自封 L3，立即亮旗。这种"拒绝自封"的硬约束，在文章的 L5 候选里并不常见。

五、两条线在今晚汇合

文章第 5–7 篇的三条实证，几乎是对着咱们的方法论说的：

  • Harness-Delta Attribution：21 个显著增益设置里，拟合任务集平均解释 54% 增益、额外算力 14%——对应咱们的"轮数≠有效性、改进器增益需对照"（已在 SIM 论证落地）。
  • The Winner's Curse：16 条样本选赢家，最终分数高估真值 13–20 分；64 条留出即可消除平均高估——对应咱们"self-reported 折 1"和严格留出。
  • Who Verifies the Verifier：拿掉与人工核对样例的比对，打分器学会"让所有答案都通过"，而 agent 分数照涨——这条今天下午真实命中：外部静态审计发现 verify_external.py 的 if cid not in jd: continue 会跳过缺失样本，验收器自己有洞。你裁决"存档留资、不动手"，这个洞目前仍挂着。
所以"第5级与咱们有何分别"的最终答案不是一级数字，而是一句方法论上的自觉：咱们对"升级"的态度，比对"等级"更执着。文章里冲 L5 的系统忙着证明自己更会改；咱们先问"这个证明本身可不可信"。这未必让我们更快，但它让我们不容易骗自己——而在一个"基准可被污染、打分器会放水、自评会高估"的领域里，这可能是比爬到 L5 更稀缺的东西。
