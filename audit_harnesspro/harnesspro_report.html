二、论文核心：自生成判据评估自生成改进

HarnessPro 把「agent harness」（管理 LLM 与环境交互的软件运行时层：prompts/tools/skills/context/memory/hooks/verification）当作可进化对象。多 Agent 框架读执行轨迹→诊断失败与冗余→规划不同性能/成本优先级的更新→editor 实现候选→test-synthesis agent 生成测试评估候选→Pareto 过滤与 lite/medium/heavy 三档选择→进入下一轮。目标 min(−PR, C) s.t. PR ≥ PR(h₀)。宣称 GPT-5.5×Codex 下 heavy 相对 RHO 平均 +2.0pp pass-rate、-26.1% cost。

但精研的锋利处不在这些数字，而在它的评估判据结构：整个优化过程是 label-free（无 ground-truth/official tests/grader feedback），候选用 LLM 合成的固定测试 S(x)=TestSynth(x,τ_h₀(x)) 评估。也就是说——用系统自己生成的判据，去评估系统自己生成的改进。

五、缺口判定：25 道门禁无一判「判据来源可信度前提」

编译前核验覆盖差集：proof_boundary_honesty(§71) 判形式化/密码学证明边界（承诺锚独立/证明范围）；verification_boundary_honesty(§76) 判「绿灯只证明一件事」的经验性通过声明；finance_blind_test/retrospective 只是文本出现 label-free/召回词，非判据。无一判「一个用自生成判据评估自生成改进的系统，是否诚实披露判据本身的可信度前提」——这是比「通过声明」「证明边界」更前一层的拦截面：评估判据从哪来、召回多少、外部锚定否、有无独立评审。拦截面独立、会拦、可迁移（任何 self-assessed/self-generated criterion 系统适用），KB-META01 会拦才入通过。
