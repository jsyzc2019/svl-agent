四、决定性发现（按严重度）

F1 · 门禁是"填表裁判"，判定智能在门禁之外 [CRITICAL]

对全部 check_* 做 AST 扫描：28/28 只接收调用方填好的字符串/布尔值，0 个读取论文、网页、日志或任何原始证据。门禁能防的是"填错/填字面串/漏填维度"，防不了"填对了标签但结论是假的"。

后果：所谓"会拦门禁"拦的是声明的一致性，不是事实的真实性。这与本仓自己在 §77 写下的 criterion_origin_honesty（自生成判据评估自生成改进的困境）是同一个未解问题。

实测 扫描脚本统计 28 个函数，reads_evidence=0；典型如 context_override_boundary.py:60-67 四个参数全是外部传入的 yes/no/partial。

F2 · 哈希锁与 engine 互不设防，证据链可被静默篡改 [CRITICAL]

向 audit_latent_taxonomies/prereg.json 追加 {"tampered":true} 后：prereg.sha256 失配（正确），但 engine.py 仍输出 anchor_all_passed: True / gate_all_passed: True / ALL: True。锁是"声明性装饰"，没有执行者。

实测 篡改→失配→engine 照跑→恢复；全过程已还原，工作区干净。另发现 audit_multimodal_memory/manifest.sha256 是多行清单格式，与其余单行格式不统一（脚本误判 1 处，非真实失配）。

F3 · 证据链纪律是渐进加严的，历史目录不统一 [HIGH]

32 个 audit 目录中，五件套（manifest/prereg/gate_prereg/engine/result）齐全仅 15 个；17 个不完整，其中 3 个（audit_fg_compare、audit_random、audit_wbcursor）连 engine/result 都没有。纪律是最近才固化，早期证据不可同口径复核。

F4 · 自进化曲线在封闭玩具世界，不外推 [HIGH]

DETAIL_BANK 固定 10 个词（收音机/缝纫机/自行车…）、simulate_session 4 类剧本、lab_spec() 写死两条原话、worlds_by_difficulty(60, gap, seed=100)。README 的"攻击成功率 100%→33%""价值余弦 0.982""留出预测 94%"均是这些固定种子上的结果。

这是合法的方法演示，但 README 以"天道运行规律的可计算形态"等措辞陈述，读者极易误读为系统已具备现实世界的自进化能力。诚实边界本应更醒目。

F5 · 反虚荣门禁使用代理指标，闭环"自证" [HIGH]

retro_audit.audit_4_feedback_loop() 判定"反哺闭环落地"的条件之一是 len([it for it in kb.items if "RETRO" in id or "SSQ" in id]) >= 6——用"库里有几条 ID 含关键词的条目"证明"复盘教训被下次任务消费"。这是代理指标自证，不是端到端消费证据。

F6 · 文档实效性漂移 [MEDIUM]

README 顶部仍写"完整推导见 commentary.md（§1–§40）"，实际已到 §88；README 包结构未列 28 道 honesty/isolation/boundary 门禁；SESSION_HANDOFF §7 的统计数字刚更新但 README 未同步。对外门面落后于内核约 48 节。

F7 · 无对外入口，能力难以被外部验证/复用 [MEDIUM]

pyproject.toml 无 console_scripts；28 道门禁无生产调用点；无统一 CLI 或 API 暴露"给一段声明→出裁决→落证据"的完整能力。能力沉淀在库与测试里，未产品化。

六、可执行改进建议（按杠杆排序）

最高杠杆（解 F1，把裁判变成法官）：给门禁增加"取证模式"——让 check_* 的调用方改为传入证据对象（论文本地路径 / 原文切片 / 日志），由门禁内部做逐字命中或结构化抽取，而不是传入已填好的 yes/no。可先选 3 道高频门禁试点（如 criterion_origin_honesty、verification_boundary_honesty、proof_boundary_honesty），保持 R0–R6 骨架不变。这是从"自证"走向"他证"的唯一路径。
次高杠杆（解 F2/F3）：把 SHA256 校验写进 engine.py 的 main：启动先校验 prereg/gate_prereg/manifest 三锁，失配直接 sys.exit(1)。同时对 17 个不完整目录补链或明确标注"历史证据，非五件套"，避免同口径误读。
结构杠杆（解 F3 两条线断裂）：建一个转换层，把 KB 的 kind/mechanism/support 结构映射成 PDCA 可消费的 Opportunity（inject_opportunities 已有入口），让真实精研产物能喂给模拟器，而不是两套判据各说各话。

门面杠杆（解 F6/F7）：由脚本从 KB/测试/audit 自动生成 README 统计段与包结构门禁清单，消除手工漂移；提供一个 svl-audit console script 暴露"给声明→出裁决→落证据"。
