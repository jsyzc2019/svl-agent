五、裁决：CROSS_VENDOR_INCONCLUSIVE（数值不翻案）

关键诚实点：三份 judge 的 notes 说明文字出现 variant（P0）/negation（P1/P2），命中 prereg 事前锁定的禁用词表 → all_admissions_pass=false → 按裁决树首枝封顶 CROSS_VENDOR_INCONCLUSIVE。

查证上下文：这些词只在 judge 写给调用者的 notes 里描述文本的"否定/限定词""删改变体"现象——正是 P1 忠实性核查任务本身要求的正当语义；判据控制流并未读取 scorer_key / gt / deletion_class 字段（源码仅 re + 词集合）。这是保守准入规则的粒度误报（词边界无差别匹配），但纪律要求事后不得放宽已锁规则翻案——数值再漂亮，准入不过就 INCONCLUSIVE。本轮如实落 INCONCLUSIVE，把"准入规则粒度"作为下轮可定位可修弱点（KB-META18），绝不改阈值重跑到 CONFIRMED。

verdict = CROSS_VENDOR_INCONCLUSIVE   locks_ok = true   all_admissions_pass = false
why = 哈希锁失配或准入未全过（异厂源码含泄漏/随机/id硬编码或签名错），对照组不成立，封顶 INCONCLUSIVE。
verify.py = 8/8 ALL_OK（裁决树自洽 + l3/absolute 未抬级）
